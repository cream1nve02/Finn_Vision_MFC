iRaypleVision 영상취득 동작 방식

MFC를 모르는 사람도 버튼 클릭부터 카메라 프레임이 화면에 표시되기까지의 흐름을 따라갈 수 있도록 정리한 설명 문서입니다.

전체 그림 MFC 역할 Connect Start Grab Software Trigger Exposure Bayer Debayer 수정 위치

1. 전체 그림

이 프로그램은 MFC가 직접 카메라를 제어하는 구조가 아닙니다. MFC는 버튼과 화면 영역을 제공하고, 실제 카메라 연결과 프레임 수신은 SDK가 담당합니다.

사용자 버튼 클릭 Connect, Start Grab, Stop, Snap, Software Trigger, Exposure Set
SDK 객체 생성 CXP는 Sapera LT, GigE는 MV Viewer SDK 객체를 생성합니다.
프레임 수신/변환 Mono는 바로 표시하고, Bayer는 RGB 컬러로 Debayer합니다.
화면 표시 MFC dialog 안의 검은 영상 영역에 최신 프레임을 그립니다.
MFC UI Sapera LT MV Viewer SDK Color Conversion

2. MFC는 무엇을 하나요?

MFC가 담당하는 것

  • 버튼, 체크박스, 입력창 배치
  • 버튼 클릭 이벤트를 함수에 연결
  • 상태 메시지 표시
  • 영상 표시용 창 핸들 제공

SDK가 담당하는 것

  • 카메라/프레임그래버 검색
  • 카메라 연결 및 파라미터 설정
  • 프레임 버퍼 생성
  • 영상 취득, 트리거, 노출 제어
  • Bayer 색 변환
MFC를 처음 본다면 BEGIN_MESSAGE_MAP을 먼저 보면 됩니다. 여기에서 "어떤 버튼을 누르면 어떤 함수가 실행되는지"가 정해집니다.

4. Start Grab부터 화면 표시까지

Start Grab은 "카메라에서 프레임을 계속 받아오기 시작하라"는 명령입니다. CXP와 GigE는 SDK가 달라 내부 흐름이 조금 다릅니다.

구분 CXP GigE
시작 함수 m_xfer->Grab() IMV_StartGrabbing()
프레임 수신 Sapera transfer callback 호출 worker thread에서 IMV_GetFrame() 반복
Mono 표시 SapView::Show() Mono8을 BGRA grayscale로 변환 후 StretchDIBits()
Bayer Color 표시 SapColorConversion::Convert() 후 SapView::Show() IMV_PixelConvert()로 BGRA8 변환 후 StretchDIBits()

CXP 프레임 흐름

Grab() 프레임그래버가 카메라 데이터를 받기 시작합니다.
Buffer 채움 SapBufferWithTrash에 프레임이 들어옵니다.
Callback Bayer면 conversion processing 실행, Mono면 바로 표시합니다.
Display SapView::Show()로 MFC 화면 영역에 표시합니다.

GigE 프레임 흐름

StartGrabbing() GigE 카메라 acquisition을 시작합니다.
GetFrame() worker thread가 프레임을 가져옵니다.
Pixel Convert Mono8 또는 BGRA8로 변환합니다.
GDI Display StretchDIBits()로 화면에 그립니다.

5. Software Trigger는 왜 Start Grab 후에 누르나요?

소프트웨어 트리거는 "지금 한 장 찍어라"라는 카메라 명령입니다. 하지만 프로그램이 프레임을 받을 준비를 하지 않으면, 카메라가 찍은 프레임을 프로그램이 놓칠 수 있습니다.

Trigger mode 체크 카메라를 자유 실행 모드가 아니라 trigger 대기 모드로 바꿉니다.
Start Grab 프로그램이 프레임을 받을 준비를 합니다.
Software Trigger 카메라에 한 프레임 촬영 명령을 보냅니다.
프레임 표시 트리거마다 한 장씩 들어와서 표시됩니다.
설정 의미
TriggerSelector = FrameStart 프레임 시작을 트리거 대상으로 선택합니다.
TriggerSource = Software 외부 라인이 아니라 API 명령으로 트리거합니다.
TriggerMode = On 카메라를 트리거 대기 상태로 둡니다.
TriggerSoftware 실제로 한 장 찍으라는 명령입니다.

6. Exposure 변경은 무엇을 하나요?

Exposure는 센서가 빛을 받는 시간입니다. 값이 길수록 밝아지지만 움직임이 흐려질 수 있고, 값이 짧을수록 어두워지지만 빠른 물체에 유리합니다.

설정 순서

  1. 입력창에서 microsecond 단위 값을 읽습니다.
  2. ExposureAuto = Off를 시도합니다.
  3. ExposureTime 설정을 시도합니다.
  4. 실패하면 ExposureTimeAbs를 시도합니다.
  5. CXP는 Sapera acquisition parameter fallback도 시도합니다.

Grab 중 변경

현재 구현은 Grab 중에도 Exposure Set 버튼을 누를 수 있게 되어 있습니다. 단, 실제 반영 여부는 카메라 feature가 acquisition 중 writable인지에 따라 달라질 수 있습니다.

7. Bayer와 Debayer 이해하기

Bayer Color 카메라는 픽셀 하나가 완성된 RGB 값을 갖고 있지 않습니다. 센서 위에 R/G/B 필터가 배열되어 있고, 각 픽셀은 한 색 정보만 갖습니다.

이 상태로 보면 컬러가 아니라 raw 패턴처럼 보입니다.

Debayer 결과

Debayer는 주변 픽셀을 참고해서 각 픽셀의 빠진 R/G/B 값을 계산합니다. 그 결과 일반적인 RGB 컬러 이미지가 됩니다.

  • CXP: SapColorConversion
  • GigE: IMV_PixelConvert
Bayer 옵션은 카메라가 Bayer raw를 출력할 때만 켭니다. Mono 카메라에서 켜면 색 변환이 지원되지 않거나 원치 않는 표시가 될 수 있습니다.
