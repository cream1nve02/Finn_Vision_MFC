MFC란? — 한 줄 요약

Windows GUI 프로그램을 C++로 만들기 위한 클래스 라이브러리입니다.

Python으로 GUI를 만들 때 tkinter를 쓰고, 로봇 시스템에 ROS를 쓰죠? MFC는 Windows GUI에서 그 역할을 합니다.

핵심 공통점: MFC, ROS, tkinter 셋 다 "이벤트/메시지가 오면 등록된 콜백을 실행"하는 구조입니다.
이 구조만 이해하면 MFC의 90%는 끝!

Python (tkinter)

import tkinter as tk

root = tk.Tk()
root.title("내 앱")

btn = tk.Button(root,
    text="클릭",
    command=on_click)
btn.pack()

root.mainloop()  # 이벤트 루프

ROS (rospy)

import rospy
from std_msgs.msg import String

def callback(msg):
    print(msg.data)

rospy.init_node('my_node')

rospy.Subscriber(
    '/topic',
    String,
    callback)

rospy.spin()  # 이벤트 루프

C++ (MFC)

// App 클래스
class MyApp : public CWinApp {
  BOOL InitInstance() {
    MyDlg dlg;
    dlg.DoModal();
    // ↑ 이벤트 루프 시작
  }
};

// 전역 객체 (자동 시작)
// = rospy.init_node()
MyApp theApp;

핵심 개념 1: 메시지 루프 (Message Loop)

Windows 프로그램은 "무한 루프를 돌면서 이벤트를 기다리는" 구조입니다.

ROS의 rospy.spin(), tkinter의 root.mainloop()과 완전히 같은 원리입니다.
"메시지가 왔나? 이벤트가 발생했나?" 를 계속 체크하는 무한 루프.

Python (tkinter)

# tkinter 내부에서 이런 일이 벌어짐
while True:
    event = wait_for_event()
    if event.type == "button_click":
        call_handler(event)
    elif event.type == "close":
        break

ROS (rospy.spin)

# rospy.spin() 내부에서 이런 일이 벌어짐
while not rospy.is_shutdown():
    msg = wait_for_message()
    if msg.topic == "/cmd_vel":
        vel_callback(msg)
    elif msg.topic == "/image":
        image_callback(msg)

MFC (DoModal 내부)

// MFC가 내부적으로 돌리는 루프
MSG msg;
while (GetMessage(&msg, NULL, 0, 0))
{
    TranslateMessage(&msg);
    DispatchMessage(&msg);
    // → 해당 창의 핸들러 호출
}

핵심 개념 2: 메시지 맵 (Message Map)

"이 이벤트가 오면 이 함수를 실행해라" 는 연결표(라우팅 테이블)입니다.

ROS에서 rospy.Subscriber('/topic', MsgType, callback)으로 토픽-콜백을 등록하죠?
MFC에서는 ON_BN_CLICKED(버튼ID, 함수)로 버튼-핸들러를 등록합니다. 완전히 같은 패턴!

Python 딕셔너리

# 이벤트 → 함수 매핑
handlers = {
    "btn_connect": on_connect,
    "btn_start":   on_start,
    "btn_stop":    on_stop,
}

# 이벤트 발생 시
func = handlers[event.source]
func()

ROS Subscriber

# 토픽 → 콜백 매핑
rospy.Subscriber(
    '/connect_cmd', Bool,
    on_connect)
rospy.Subscriber(
    '/start_cmd', Bool,
    on_start)
rospy.Subscriber(
    '/stop_cmd', Bool,
    on_stop)

MFC 메시지 맵

// 버튼ID → 핸들러 매핑
BEGIN_MESSAGE_MAP(Dlg, CDialogEx)
  ON_BN_CLICKED(
    IDC_BTN_CONNECT,
    &Dlg::OnBnClickedConnect)
  ON_BN_CLICKED(
    IDC_BTN_START,
    &Dlg::OnBnClickedStart)
  ON_BN_CLICKED(
    IDC_BTN_STOP,
    &Dlg::OnBnClickedStop)
END_MESSAGE_MAP()
정리하면:
ROS: Subscriber(토픽, 메시지타입, 콜백) — "이 토픽에 메시지 오면 이 함수 실행"
MFC: ON_BN_CLICKED(버튼ID, 핸들러) — "이 버튼이 클릭되면 이 함수 실행"

BN = Button Notification, IDC = ID of Control (버튼 고유 번호, resource.h에 #define)

핵심 개념 3: 다이얼로그 기반 앱

이 프로그램은 "다이얼로그(대화상자) 하나가 곧 메인 화면"인 구조입니다.

ROS로 치면 노드 하나에 subscriber/publisher 다 때려넣은 구조입니다.
Python으로 치면 root = tk.Tk() 하나에 버튼 다 붙인 구조. 창 하나 = 프로그램 전체.

이 앱의 구조를 Python과 ROS 노드로 각각 번역하면:

ROS 노드로 번역하면 이런 느낌

#!/usr/bin/env python
import rospy
from sensor_msgs.msg import Image

class GrabberNode:               # = CiRaypleCxpGrabberDlg
    def __init__(self):
        rospy.init_node('grabber')  # = theApp + InitInstance()
        self.camera = None          # = m_acq
        self.image_pub = rospy.Publisher(  # = m_view
            '/camera/image', Image, queue_size=1)

        # 메시지 맵과 같은 역할! 토픽 → 콜백 등록
        rospy.Subscriber('/cmd/connect', Bool,
            self.on_connect)          # = ON_BN_CLICKED(IDC_BTN_CONNECT, ...)
        rospy.Subscriber('/cmd/start', Bool,
            self.on_start)            # = ON_BN_CLICKED(IDC_BTN_START, ...)

    def on_connect(self, msg):        # = OnBnClickedConnect()
        self.camera = Camera(...)

    def on_start(self, msg):          # = OnBnClickedStart()
        self.camera.start_grab()

    def image_callback(self, image):  # = XferCallback (프레임 도착 콜백)
        self.image_pub.publish(image) # = m_view->Show()

if __name__ == '__main__':
    node = GrabberNode()
    rospy.spin()                      # = DoModal() 메시지 루프

Python tkinter로 번역하면

class MyApp:              # = CiRaypleCxpGrabberApp
    """프로그램 자체"""
    def run(self):
        dlg = GrabberDialog()
        dlg.show_modal()  # = DoModal()

class GrabberDialog:      # = CiRaypleCxpGrabberDlg
    """메인 화면"""
    def __init__(self):
        self.camera = None    # = m_acq
        self.buffer = None    # = m_buffers
        self.transfer = None  # = m_xfer
        self.view = None      # = m_view

    def on_connect(self):     # Connect 클릭 시
        self.camera = Camera(...)
        self.transfer = Transfer(
            callback=self.on_frame)

    def on_start(self):       # Start 클릭 시
        self.transfer.grab()

    def on_frame(self, image):  # 프레임 도착 콜백
        self.view.show(image)

app = MyApp()   # = theApp
app.run()

핵심 개념 4: 리소스 파일 (.rc)

버튼 위치, 크기, 텍스트를 코드가 아니라 별도 파일에 정의합니다.

HTML에서 <button>으로 UI를 정의하고 JS로 로직을 짜는 것처럼,
MFC는 .rc 파일에서 UI 레이아웃을, .cpp 파일에서 동작을 정의합니다.
// iRaypleCxpGrabber.rc (리소스 파일) — HTML처럼 UI 레이아웃 정의 IDD_IRAYPLECXPGRABBER_DIALOG ← 다이얼로그 이름 (= 화면 ID) BEGIN // 종류 ID x y 가로 세로 CONTROL "", IDC_VIEW_WND, 10, 10, 570, 420 ← 카메라 영상 영역 PUSHBUTTON "Connect", IDC_BTN_CONNECT, 596, 18, 140, 24 ← 버튼 PUSHBUTTON "Start", IDC_BTN_START, 596, 50, 66, 24 PUSHBUTTON "Stop", IDC_BTN_STOP, 670, 50, 66, 24 EDITTEXT IDC_EDIT_EXPOSURE, 596,220, 86, 18 ← 입력칸 END // IDC_BTN_CONNECT = 1001 (resource.h에 정의된 숫자) // 이 숫자가 메시지 맵에서 버튼을 식별하는 열쇠!

프로그램이 켜질 때 무슨 일이 벌어지나?

.exe를 더블클릭하면 아래 순서로 실행됩니다. 각 단계를 쉽게 풀어볼게요.

1 Windows가 .exe 파일을 메모리에 로드
더블클릭하면 Windows가 프로그램을 메모리에 올리고, C++ 런타임을 시작합니다.
이때 전역 변수들이 먼저 생성됩니다.
▼
2 전역 객체 theApp 생성 (자동)
C++에서는 전역 변수가 main() 이전에 자동 생성됩니다.

ROS 비유: rospy.init_node('grabber')가 노드를 등록하는 것과 같은 시점.
Python 비유: 파일 맨 위에 app = MyApp() 써놓으면 import 시점에 바로 만들어지는 것과 비슷.
// iRaypleCxpGrabber.cpp 36번째 줄 CiRaypleCxpGrabberApp theApp; // 이 한 줄이 프로그램의 시작점! // main() 함수가 보이지 않는 이유: // MFC가 WinMain()을 대신 제공하고, // 그 안에서 theApp의 InitInstance()를 호출합니다.
▼
3 MFC가 theApp.InitInstance() 호출
MFC 프레임워크가 숨겨진 WinMain() 안에서 theApp.InitInstance()를 호출합니다.
이게 사실상 main() 함수입니다.
// iRaypleCxpGrabber.cpp 41번째 줄 BOOL CiRaypleCxpGrabberApp::InitInstance() { // 1) Windows 공용 컨트롤 초기화 (버튼, 체크박스 등 쓰려면 필요) InitCommonControlsEx(&InitCtrls); // 2) 메인 다이얼로그(화면) 만들기 CiRaypleCxpGrabberDlg dlg; // 메인 화면 객체 생성 m_pMainWnd = &dlg; // "이게 메인 화면이야" 등록 // 3) 화면 띄우기 — 여기서 멈춤! 창이 닫힐 때까지 안 넘어감 INT_PTR nResponse = dlg.DoModal(); return FALSE; // 창 닫히면 프로그램 종료 }
▼
4 DoModal() 내부에서 OnInitDialog() 호출
DoModal()이 창을 만들면서 OnInitDialog()를 자동으로 호출합니다.
ROS 비유: __init__에서 subscriber/publisher 등록하고 파라미터 세팅하는 것과 같습니다.
Python 비유: __init__ 에서 위젯 초기 설정 하는 것과 같습니다.
// iRaypleCxpGrabberDlg.cpp 117번째 줄 BOOL CiRaypleCxpGrabberDlg::OnInitDialog() { CDialogEx::OnInitDialog(); // 부모 클래스 초기화 (super().__init__()) SetIcon(m_hIcon, TRUE); // 아이콘 설정 SetDlgItemText(IDC_EDIT_EXPOSURE, _T("10000")); // 기본값 세팅 CheckDlgButton(IDC_CHECK_BAYER, BST_UNCHECKED); // 체크박스 해제 UpdateUiState(); // 버튼 활성/비활성 설정 return TRUE; }
▼
5 메시지 루프 시작 — 사용자 입력 대기
DoModal() 안에서 무한 루프가 시작됩니다.
이제부터 사용자가 버튼을 클릭하면 이벤트가 처리됩니다.
